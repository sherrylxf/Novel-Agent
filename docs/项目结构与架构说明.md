# Novel Agent 项目结构与架构说明

本文档说明仓库目录组织、Maven 多模块划分、分层职责与典型请求链路，便于新人上手与二次开发。

## 一、仓库顶层结构

| 路径 | 说明 |
|------|------|
| `pom.xml` | 父 POM，聚合子模块、统一依赖与插件版本 |
| `ai-agent-station-study-*` | 各业务与技术模块（见下节） |
| `docs/` | 运维、数据存储、流程与 RAG/图谱等说明（见「相关文档」） |
| `.env.example` | 本地/容器环境变量示例 |

根目录另有 `README.md`、`使用指南.md`、`配置和运行指南.md` 等，与 `docs/` 内文档互补。**部署与 PostgreSQL/pgvector 初始化**以 `docs/dev-ops/README.md` 与 `docs/dev-ops/pgvector/init.sql` 为准。

## 二、Maven 与 Java 包名约定

- 父 POM 的 **`groupId` 为 `cn.bugstack.ai`**（历史命名），与 **源码包名无关**。
- 业务与契约代码统一放在 **`cn.bugstack.novel.*`** 下（如 `cn.bugstack.novel.api`、`cn.bugstack.novel.domain`）。
- **请勿**在 `src/main/java` 下新建 **`cn/bugstack/ai/...`** 空目录；若 IDE 按 groupId 生成树形结构，无对应 `.java` 文件时应删除，避免与真实包混淆。

## 三、Maven 多模块

| 模块 | 职责 |
|------|------|
| **ai-agent-station-study-api** | 对外契约：服务接口（如 `INovelAgentService`）、请求/响应 DTO，供 app 实现、供 trigger 引用 |
| **ai-agent-station-study-app** | **Spring Boot 启动与装配**：`Application`、数据源与线程池、Spring AI / 向量库 / Neo4j / Redis 等 Bean 配置，`application-*.yml` |
| **ai-agent-station-study-domain** | **领域核心**：小说生成编排（`NovelAgentOrchestrator`）、各类 Agent、**生成流水线扩展点**（`IGenerationPipelineHandler`）、执行链节点、实体与领域服务接口（RAG、知识图谱、续写、计划、护栏 `INovelGenerationGuard` 等） |
| **ai-agent-station-study-trigger** | **接入层**：REST Controller（如 `NovelController`、`RAGController`、`KnowledgeGraphController` 等）、HTTP/SSE 适配 |
| **ai-agent-station-study-infrastructure** | **基础设施实现**：MyBatis 仓储、向量检索（`VectorRAGService`、Redis 缓存装饰）、Neo4j、文件导出、Redisson 护栏实现等 |
| **ai-agent-station-study-types** | **公共枚举与异常**：如 `AgentType`、`GenerationStage`、`NovelGenre`、`NovelAgentException`，供 domain / trigger 等引用 |

依赖方向（概念上）：**trigger → app/domain/types**；**infrastructure → domain**（实现接口）；**app** 负责把 infrastructure 的实现绑定到领域接口。

## 四、分层与包职责（domain / infrastructure）

### 4.1 领域层（`ai-agent-station-study-domain`）

- **`domain/agent`**：小说生成相关智能体（规划、章节、场景、抽取、校验等）及 **`NovelAgentOrchestrator`**（编排、阶段推进与重试）。
- **`domain/agent/pipeline`**：生成流水线 Handler 接口（`IGenerationPipelineHandler`），与执行链配合扩展步骤。
- **`domain/agent/service/execute/chain`**：执行链节点（根/种子/卷/章/场景等），驱动生成步骤。
- **`domain/model`**：实体与值对象（小说、章节、场景、计划、上下文等）。
- **`domain/service`**：领域服务接口（RAG、知识图谱、续写、计划、导出、**护栏** `INovelGenerationGuard` 等）。

领域层**不依赖**具体数据库驱动或 HTTP，只依赖接口与模型。

### 4.2 基础设施层（`ai-agent-station-study-infrastructure`）

- **`adapter/repository`**：持久化实现（对接 MyBatis Mapper）。
- **`adapter/rag`**：向量检索与 Spring AI 集成；可含 Redis 缓存装饰。
- **`adapter/kg`**：Neo4j 知识图谱相关实现。
- **`adapter/export`**：章节文件落盘等。
- **`guard`**：Redisson 限流、场景锁等（实现领域护栏接口）。

### 4.3 应用层（`ai-agent-station-study-app`）

- **`config`**：`DataSourceConfig`（PostgreSQL 统一数据源）、`VectorStoreConfig`、`Neo4jConfig`、`LLMClientConfig`、线程池、`NovelPipelineConfiguration` 等。
- **`resources/application-*.yml`**：按环境切换数据源、Redis、Neo4j、模型端点等。

### 4.4 触发器层（`ai-agent-station-study-trigger`）

- `trigger/http` 下各 Controller：接收 HTTP（及 SSE），校验后调用领域或应用服务，返回 DTO。

## 五、典型数据与调用链路（简图）

```
HTTP 请求
  → trigger（Controller）
  → domain（Orchestrator / 流水线 Handler / 执行链 / Agent）
  → infrastructure（RAG、DB、Neo4j、Redis、文件）
  → 可选：外部 LLM API
```

- **业务与向量**：以 **PostgreSQL** 为主库，**pgvector** 存向量（表结构见 `docs/dev-ops/pgvector/init.sql`）。
- **图与关系**：**Neo4j**（若配置可用）。
- **Redis**：RAG 缓存、生成护栏（限流、分布式锁等）；键前缀与语义见 `docs/数据存储总览.md`。

## 七、阅读代码的建议顺序

1. `ai-agent-station-study-app/.../Application.java` 与 `config` 包 — 启动与 Bean 装配。
2. `domain/.../NovelAgentOrchestrator.java`、`agent/pipeline`、`execute/chain` — 生成主流程与扩展点。
3. `trigger/http` 下 Controller — API 入口。
4. `infrastructure` 中 RAG、Repository、Neo4j、`guard` — 持久化与横切能力。
